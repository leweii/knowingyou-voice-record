# 已知问题（发布前遗留）

S20 边界情况测试中确认的、决定不在本轮修复的 P1 问题。都不是 P0（不会丢录音、不会崩溃、不会权限死循环）——都是「某个小概率场景下功能没有优雅降级」，记录下来以便下一轮排期。

## P1-1：保存目录在录制中途被删除 / 外置盘拔出，不会自动切换备用目录

**对应场景**：S20 矩阵 #4（[manual-matrix.md](manual-matrix.md)）

**现状**：`RecordingSession.start()` 在开录前用 `FileManager.default.isWritableFile` 检查目录可写性,不可写会在开录前失败——这部分已覆盖。但录制**开始之后**,如果保存目录所在的卷被拔出或目录被删除,当前实现没有检测这个情况并切换到备用目录（如 `~/Documents/知鱼录音`）,写入会持续失败直到触发 S20 新增的「连续 3 次写失败→`.diskFull`→自动停止」路径，把这类情况和「磁盘真的满了」混为一谈处理（结果都是停止并尽量保存,不会更糟,但通知文案会说「磁盘空间不足」而不是「保存目录不可用」，文案不准确）。

**为什么不在本轮修）**：需要新增一条独立的错误路径（区分「磁盘满」vs「卷已拔出」需要判断具体 errno / `NSFileWriteVolumeReadOnlyError` 等）,以及备用目录切换后如何让用户找到文件（目录切换要写事件到 notes,还要在 UI 上提示"本次录音保存到了备用目录"）,是一块独立的功能量,不适合在 S20 的"边界情况扫尾"范围里顺手加。

**风险评估**：触发条件是外置盘录制时中途拔盘,这种用法本身就不常见（存储路径设置里有可写性检查,大多数人会用内置盘）；触发后不丢数据,只是通知文案不够精确。

## P1-2：录制中的 `.caf` 文件被用户在 Finder 里手动删除，停止时转码会失败

**对应场景**：S20 矩阵 #12（[manual-matrix.md](manual-matrix.md)）

**现状**：录制期间文件描述符已经打开,POSIX 语义下 Finder 删除只是移除目录项,写入本身不受影响,一直到 `stop()`。但 `stop()` 阶段的转码（`.caf` → `.m4a`）依赖通过**路径**重新打开文件（`AVAssetExportSession` / `AVAudioFile` 走的是路径,不是复用已打开的 fd）,如果这时候路径已经不存在,转码会抛错,整段录音丢失（即便音频数据其实还在被删除前打开的那个 fd 对应的 inode 里,只是没有任何目录项指向它,常规 API 拿不到）。

**为什么不在本轮修）**：要做到"目标不存在则重建"需要在写入路径这一层就保留一个独立于目录项的引用（比如始终通过已打开的 `fd` 做后续操作而不是重新按路径 open）,这触及 `RecordingSession`/`Encoder` 的文件句柄生命周期设计,风险和工作量都超出 S20 的边界情况扫尾范围。

**风险评估**：触发条件是用户在录音应用毫无提示的情况下主动去 Finder 删除一个看起来还在被使用的文件,是很反常的操作路径,不属于用户会在正常使用中意外触发的场景。
